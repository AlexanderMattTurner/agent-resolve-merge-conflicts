- The contradictory-merge check no longer counts how often a line appears. Two parents that each add their own test both write the same boilerplate assertion, and the count read that as a doubled block: every warning it raised on a real merge was refuted by hand. A duplicate signature is mergiraf's to report, and a doubled definition is named by the caller's own linters through `post-merge-check-command`.
- The merge-delta report reads git's own three-way merge again. `git merge-tree` re-runs the merge, so a checkout that registers a driver (`merge=mergiraf`) answered through it, and every delta that driver resolved was invisible to the self-review whose job is finding content in neither parent.
- A line either parent's own blob still holds is no longer reported as content neither side wrote. The mechanical merge drops a line one side deleted in text the other never touched, so a resolution that restores it traced to nothing.
- A refusal over a post-merge check that wrote to the tree now names the paths it wrote. The command's name alone left no way to find the writer short of reproducing the merge.
- The pre-push self-review reserves the wall clock one fix round needs, so a finding it has already narrowed to one line is corrected instead of handing every path in the merge to a person.
- A conflict in an output the caller declares hand-resolved is declined with the caller's own reason instead of costing a model shard.
- A draft carrying `approved` or `force-queue` is resolved. A ready-PR cap holds a conflicted PR back because it cannot land, and the resolver skipped it for being a draft, so nothing repaired the conflict that made it unlandable. `SESSION_BRANCH_PREFIXES` now overrides the parked-draft prefix in Python as it already did in shell.
- The "working on it" comment says when the run is killed, so a reader can tell a live run from a dead one.
