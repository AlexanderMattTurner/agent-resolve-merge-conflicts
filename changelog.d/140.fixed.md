- The resolver names a merge that kept BOTH parents' version of one statement, where the two are each other's negation — an `assert x in y` from one side beside an `assert x not in y` from the other. Every such line traces to a parent, so no conflict, no neither-side line and no delta review saw it before.
- It reads the two parents' added lines rather than a conflict region, because git merges that pair cleanly. A pair counts only at one indentation, within ten lines of each other in the merged file, and only when both survived into it.
- Such a merge still lands: auto-resolve names the lines on the pull request and turns auto-merge off, the way it already does for a line neither side wrote.
