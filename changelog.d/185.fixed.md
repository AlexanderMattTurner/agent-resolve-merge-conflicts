- A resolution that keeps one parent's whole file, while the other parent changed that same file since the merge base, is now a finding. The resolver gives it one bounded repair pass, and a finding that survives turns auto-merge off.
- A bash function one side added and called, that the merge keeps while dropping every call to it, is now a finding too. The shell twin of the orphaned-binding check the resolver already ran over Python.
- The post-merge check's failure attribution no longer builds a virtual environment per parent. When a parent's `uv.lock` and `pyproject.toml` are the merged tree's bytes, its run reuses the workspace `.venv` and the caller's opening `uv sync` is a no-op.
