- A regen rule may declare `releasedBy` for a file a release workflow writes, or `deletionWins: true` for an ignored generated output. When a pull request deleted such a file and the base rewrote it, the resolver keeps the deletion. When both sides rewrote a release-owned file, it takes the base's copy whole. When the base deleted it and the pull request rewrote it, or a side renamed it, a human decides.
- A failed regeneration now puts the command, its exit code and the last 30 lines of its stderr in the pull request comment, names the paths left for a human, and applies `auto-resolve-blocked`. When a required check re-derives every path left, the rest of the merge lands.
